I see a bit of confustion with our organization of folder structure and specificly
where and how to place fixures.

So before I start rearranging things I want to confirm with the team
that this is how we want to organize our fixtures.

1. Project specific fixtures
Fixtures that are used by tests "below" a certain level should
be placed in conftest.py file on that level.
Like this when the folder structure we have agred on before is in place.

comet/
    ├── conftest.py  # Fixtures for all displays
    ├── dim/
    │   ├── conftest.py  # Fixtures for dim only
    │   ├── test_module1.py
    │   └── test_module2.py
    └── hud/
        ├── conftest.py  # Fixtures for hud only
        └── test_submodule.py

This is prefered way of doing this according to pytest documentation.
No need to import fixtures from other conftest.py files, pytest will find them automatically.


2. Shared fixtures between projects
For fixtures that can be used by both comet and asteroid cant be placed in conftest.py files
unless



3 cases:
1. test that want to use the fixture defined in the same project. (Direct ancestor)

    Here we put all fixture in a conftest.py within each folder and they will be
    available to all tests in that folder and below.

    This is the preferred way of doing this according to pytest documentation.

2.test that want to use the fixtures from shared folder (not a direct ancestor)
    Here we we should define the fixture we want to use in
    pytest_plugins = [
        "shared_fixtures.db_fixtures",
    ]
    It is not good practice to import the fixture directly

    Since the fixtures are being included this way they cant be put in a conftest.py file
    since those are not allowed to be included


3. test in shared folder that want to use the fixture define in shared folder. (not direct ancestor)
    This will be same as case 2
